# GlassBlog 部署指南（甲骨文云服务器）

> 目标：本地写文章 → `发布.bat` 推送 GitHub → 去服务器执行一条命令拉取构建 → pm2 + nginx + HTTPS 上线。
> 本文按 **Oracle Cloud（Ubuntu 22.04/24.04）** 写；其他 Linux 云服务器（腾讯云/阿里云/Vultr）步骤基本一致。

> ⚠️ 关键前提：`ADMIN_MODE=cloud` 必须配置。它会让线上的 `/admin` 与所有写接口直接 404，后台只在本地使用。

---

## 0. 前置条件

| 工具 | 用途 | 检查方式 |
| --- | --- | --- |
| Node.js ≥ 20 | 本地写作 + 服务器构建 | `node -v` |
| Git | 推送/拉取代码 | `git --version` |
| GitHub 账号 | 托管源码（建议私有仓库） | github.com |
| Oracle Cloud 实例 | 运行站点（Ubuntu 镜像） | 能 SSH 登录 |
| 域名（可选但建议） | 正式访问地址 | DNS 可解析 |
| nginx + pm2 | 反向代理 + 进程守护 | 服务器上安装 |

## 1. 本地第一次推送

### ① 配置 git 身份（只需一次）

```bash
git config --global user.name "你的GitHub用户名"
git config --global user.email "你GitHub绑定的邮箱"
```

### ② GitHub 建私有仓库

GitHub → New repository → 名字随意（如 `glassblog`）→ **Private** → 不要勾选初始化选项。

### ③ 关联远程并推送

```bash
git remote add origin https://github.com/你的用户名/glassblog.git
node scripts/publish.mjs
```

> 推送时 GitHub 会要求授权，按提示完成即可。
> 如果直连被重置，先设置代理再发布：`set GIT_PROXY=http://127.0.0.1:11129`（端口改成你代理软件的端口）。

## 2. 服务器首次部署

以下命令都在服务器上执行。

### ① 开放端口

Oracle 控制台 → 实例 → 安全列表（Security List）放行 **22 / 80 / 443**；
服务器内防火墙（如启用 ufw）：

```bash
sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable
```

### ② 安装 Node 20、Git、nginx、pm2

```bash
sudo apt update
sudo apt install -y git nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
sudo npm i -g pm2
```

### ③ 克隆仓库（私有仓库用 Deploy Key）

```bash
ssh-keygen -t ed25519 -C "glassblog-server" -f ~/.ssh/glassblog -N ""
cat ~/.ssh/glassblog.pub
```

把公钥加到 GitHub 仓库 → Settings → **Deploy keys** → Add key（只读即可，不要勾写权限）。
然后：

```bash
git clone git@github.com:你的用户名/glassblog.git ~/glassblog
cd ~/glassblog
```

> 首次连 GitHub 会提示确认主机指纹，输入 `yes`。

### ④ 配置环境变量

```bash
cp .env.example .env
nano .env
```

至少要设：

```
ADMIN_MODE=cloud
```

需要 AI 助理就再填 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`（线上不能用本地 secrets，因为那个文件不进 git）。保存后退出。

### ⑤ 安装依赖、构建、启动

```bash
npm ci
npm run build
pm2 start npm --name glassblog -- start
pm2 save
pm2 startup     # 按提示执行它输出的那行命令，实现开机自启
```

此时用 `http://服务器IP:3000` 应能打开站点（Oracle 安全列表需临时放行 3000 才能直连测试；不建议长期开放）。

### ⑥ nginx 反向代理

```bash
sudo nano /etc/nginx/sites-available/glassblog
```

```nginx
server {
    listen 80;
    server_name www.xingkongly.top xingkongly.top;

    client_max_body_size 12m;   # 图片上传上限略大于应用的 10m

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用并重载：

```bash
sudo ln -s /etc/nginx/sites-available/glassblog /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

> `X-Forwarded-For` 必须保留：AI 助理与订阅接口的限流靠它识别访客 IP。

### ⑦ 域名解析

在域名控制台加记录：

- `A` 记录：`@` → 服务器公网 IP
- `A` 记录：`www` → 服务器公网 IP

等解析生效后，`config/site.json` 里把 `siteUrl` 改成 `https://你的域名`，再走一次发布流程。

### ⑧ HTTPS（Let's Encrypt）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名 -d www.你的域名
```

按提示选择自动跳转 HTTPS。证书会自动续期。

## 3. 日常发布流程

```
本地：双击 写作.bat → 写文章/改设置 → 双击 发布.bat（推送 GitHub）
服务器：ssh 登录 → cd ~/glassblog → bash scripts/deploy-server.sh
```

`deploy-server.sh` 会依次执行：`git pull --ff-only` → `npm ci` → `npm run build` → `pm2 restart glassblog`。

> 建议在服务器 `~/.bashrc` 里加别名：
> `alias gb='cd ~/glassblog && bash scripts/deploy-server.sh'`
> 以后 SSH 上去敲 `gb` 即可。

也可以在服务器上装一个 cron 定时拉取（例如每 10 分钟），但**不建议**：文章发布时机不可控，手动执行更稳。

## 4. 数据与备份

| 数据 | 位置 | 是否进 git | 备份建议 |
| --- | --- | --- | --- |
| 文章/说说/选刊 | `content/` | 是 | 随 GitHub 仓库 |
| 站点配置 | `config/site.json` | 是 | 随仓库 |
| 密钥 | `config/secrets.local.json` | **否** | 本地自行备份 |
| 订阅邮箱 | `data/subscribers.jsonl` | **否** | 定期 scp 备份 |
| 上传图片 | `public/uploads/` | 是（随仓库） | 随仓库；量大时切外部图床 |
| 线上环境变量 | 服务器 `.env` | **否** | 自行备份 |

服务器上查看订阅者：

```bash
cd ~/glassblog
node scripts/subscribers.mjs count     # 数量
node scripts/subscribers.mjs list      # 列表
node scripts/subscribers.mjs export    # 导出 CSV 到 data/
```

> `data/` 目录必须可写：`mkdir -p ~/glassblog/data`，并确认运行 pm2 的用户有写权限。

## 5. 排错速查

| 症状 | 原因与解法 |
| --- | --- |
| `写作.bat` 闪退 | 右键"在终端中打开"手动运行看报错；多半是没装 Node |
| 推送报 `Connection was reset` | 直连 GitHub 被重置。设置 `GIT_PROXY` 后重发；未设置时会直接提示 |
| 推送被拒 `non-fast-forward` | 服务器或别处有提交。先 `git pull --rebase origin main` 再发布 |
| 网站 502 | `pm2 status` 看进程是否在跑；`pm2 logs glassblog` 看报错；确认端口 3000 被占用情况 |
| 域名打不开 / 证书失败 | 安全列表与 ufw 是否放行 80/443；DNS 是否解析到该 IP |
| 线上能打开 `/admin` | **危险**：检查服务器 `.env` 是否有 `ADMIN_MODE=cloud`，改完 `pm2 restart glassblog --update-env` |
| 线上文章没更新 | `deploy-server.sh` 是否执行成功；构建失败多半是某篇文章 YAML 头格式错误 |
| 图片 404 | 确认图片已随 `发布.bat` 提交；服务器构建后重启；或改用外部图床 |
| 订阅提交失败 | `data/` 是否有写权限；`pm2 logs` 查看具体报错 |
| 服务器 `git pull` 冲突 | 不要在服务器上手改代码；`git status` 查看后 `git checkout -- .` 放弃改动再拉取 |
| 上传大图失败 | nginx `client_max_body_size` 太小（本指南设为 12m） |

## 6. 安全清单（上线前过一遍）

- [ ] 服务器 `.env` 已设 `ADMIN_MODE=cloud`，线上 `/admin` 返回 404
- [ ] `config/secrets.local.json` 不在 git 里（`.gitignore` 已兜底）
- [ ] 服务器 `.env` 不在 git 里（`.gitignore` 已兜底，`.env.example` 是模板）
- [ ] 本地后台密码已从默认 `glassblog` 改掉
- [ ] `site.json` 里 ICP 备案号已填（如需国内合规；甲骨文海外机房无法备案）
- [ ] AI API key 只存在本地 secrets 或服务器 `.env`，从未写进文章/截图
- [ ] `data/` 目录可写且不在 git；已安排备份
- [ ] 防火墙只开放 22/80/443，3000 不对公网开放
- [ ] HTTPS 已生效，HTTP 自动跳转
- [ ] 线上后台不可用时，用 `node scripts/subscribers.mjs export` 导订阅列表

## 附：为什么不用 Vercel 了

本项目已改为 **自建服务器 + nginx** 路线：
- 甲骨文海外机房 + 自有域名，无需 ICP 备案也能上线；
- 订阅邮箱、每日选刊生成等需要本地磁盘写入的能力，自建服务器天然支持；
- 部署成本为零（免费实例足够个人博客），代价是需要自己维护 nginx/pm2/证书。

如果以后仍想用 Vercel，代码本身兼容（Next.js 原生），但需注意：订阅数据会落在临时磁盘、无法持久化，`data/` 需换数据库或对象存储。
